# История изменений (Changelog)

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версионирование — по принципу `MAJOR.MINOR.PATCH` с инкрементом версии в исходнике
(`APP_VERSION`) при каждой доработке. Начиная с v1.55 собранный `.exe` содержит
версию в имени файла (`MFC_Flasher_v<VER>.exe`).

## [1.59] — 2026-10-12

### Изменено (редактор сценария прошивки, UI)
- **Правило выбора типа прошивки по директории источника**: файлы из `full/`
  можно прошивать как `apply` или `boot`; из `apply/` — только `apply`;
  из `boot/` — только `boot`. Валидация при записи plan.xml проверяет
  допустимость выбранного типа.
- **Пустой путь к файлу** — флаг выбора типа автоматически снимается и
  блокируется до появления файла.
- **«Выбрать все»** выбирает только строки, удовлетворяющие условиям прошивки
  (модуль доступен для прошивки + непустой путь к файлу).
- **Резервы широких модулей** (вторые слоты CPU и т.п.): поле «Путь к файлу»
  пустое и неактивное.
- Убраны колонки **Маркер**, **Производитель**, **Тип**; надпись «Выбор»
  выводится полностью (ширина колонки увеличена).
- Окно редактора расширено (1600×700), чтобы по возможности был виден
  полный путь к файлу прошивки.

### Добавлено
- Скан `firmware_dir` учитывает подпапки `full/`, `apply/`, `boot/`
  (`source`/`rel_path`); загрузка агента сохраняет структуру подпапок на
  устройстве в `/home/user/fw_update/images/`.
- Операция 6 (Update) перед запуском агента выполняет доказательную
  проверку/дозагрузку файлов прошивок, выбранных в СП (`_upload_selected_firmwares`).

## [1.58] — 2026-10-12

### Исправлено
- **Парсер информации о модулях (операция 10)**: уточнена семантика поля
  `index` в `module_info_arr` по данным реального устройства — это **номер
  физического слота (1-базируемый)**, т.е. `slot = index` БЕЗ смещений
  (`{"index": 1, "module_type": "CPU", "slot_count": 2}` — CPU занимает
  слоты 1 и 2; запись `index=4 DIR12` — DIR12 в слоте 4). Прежнее правило
  v1.57 `slot = index + 1` смещало все типы на +1 (CPU показывался во
  втором слоте вместо первого, POWER_UNIT — в 21 вместо 20). Запись
  `index=0` с пустым/NA типом распознаётся как артефакт бэкенда и
  пропускается (о ней появляется запись в журнале).
- Упрощена эвристика отсечения «хвоста» артефактных записей: допустимый
  шаг индексов — 1 (индексы идут подряд, резерв ширины заполнен
  NA-заглушками, схема реального устройства) либо `slot_count` предыдущей
  записи (бэкенд резервирует индексы под ширину без заглушек); сложные
  offset/width_extra ветки удалены.
- Диагностика «отвечающие модули на NA-слотах» больше не ложно срабатывает
  на резервных слотах широких модулей (тип там известен).
- Число строк в окне «Информация о модулях» ограничено реальными слотами
  креста (1..crate_slot_count), мнимые слоты за границами креста не
  создаются.
- Файл приложения переименован: `MFC_Module_Updater_v1.57.py` → `MFC_Module_Updater_v1.58.py`.

### Добавлено
- Автотест парсера `tests/test_parser_v158.py`: прогон `_fetch_module_info`
  на копии ответа реального устройства (22 записи головы + хвост-артефакт,
  широкие модули, резерв CPU) и граничных кейсах; запускается в CI.

## [1.57] — 2026-10-12

### Исправлено
- **Парсер информации о модулях (операция 10)**: полностью переработано
  сопоставление слот↔тип. Поле `index` в `module_info_arr` является
  0-базируемым номером слота (`slot = index + 1`) и используется напрямую,
  без эвристик отбрасывания «дублей», которые сами вносили смещение.
  Широкие модули (`slot_count > 1`, например CPU на 2 слота) описываются
  одной записью; соседние зарезервированные слоты помечаются тем же типом,
  но прошивка на них запрещена (`flashable=False`), даже если модуль
  отвечает серийным номером. Убраны незавершённые ветки кода (offset/flat
  эвристики), вызывавшие NameError при `slot_count > 1`.
  «Хвост» артефактных записей (на реальном устройстве — 32 записи при
  `crate_slot_count=21`: повторный счётчик индексов 0..10 с пустыми/дублирующими
  типами) теперь аккуратно отрезается по первому признаку: индекс перестал
  расти (повтор/уменьшение, включая нулевой индекс после ненулевого) либо
  превысил `crate_slot_count`. Именно этот хвост раньше создавал видимое
  смещение типов на +1 и «мнимые» слоты 22..32 за пределами креста.
  Запись головы с распознанным типом больше не затирается дублем с NA.
- Убрано ручное смещение `+1` из v1.55–v1.56: оно больше не нужно —
  `index` применяется как есть (0-база → слот с базы 1).
- Файл приложения переименован: `MFC_Module_Updater_v1.56.py` → `MFC_Module_Updater_v1.57.py`.

### Добавлено
- **Доопределение типа по отвечающему модулю**: если конфигурация креста
  молчит о слоте (нет записи или тип NA), а модуль в этом слоте отвечает —
  тип берётся из `module_arr` (`module_type`/`type`/`model`). Событие
  фиксируется в журнале («тип доопределён по ответу модуля»).
- Диагностика несоответствий в журнале: список слотов отвечающих модулей с
  типом NA; предупреждения о типах конфигурации креста, которым не отвечает
  ни один модуль; сводка «Индексы module_info_arr неубедительны» при
  переходе в позиционный режим.
- Позиционный режим сопоставления (slot = порядковый номер записи) как
  запасной вариант, если поле `index` полностью повреждено (все записи с
  одинаковым индексом). Записи с пустым/отсутствующим `index` (например,
  добавленные вручную в конфигурации креста) трактуются как артефактные и
  отбрасываются без влияния на голову массива.

## [1.56] — 2026-10-12

### Исправлено
- **Парсер информации о модулях (операция 10)**: устранено смещение типов при
  отбрасывании невалидных записей `module_info_arr`. Записи с `index<=0` или
  пустым типом, дублирующие уже описанные типы (на реальном устройстве CPU и
  DIR12 приходили повторно с `index=0`), больше не участвуют в сопоставлении
  слот↔тип: для упорядочивания используется позиционный порядок оставшихся
  записей массива ответа (элементы идут слева направо по слотам креста).
  Ранее удаление «мнимых» элементов сдвигало всю последовательность типов
  (CPU в слоте 1 отображался как NA, DIR12 съезжал на соседний слот).
- Файл приложения переименован: `MFC_Module_Updater_v1.55.py` → `MFC_Module_Updater_v1.56.py`.

## [1.55] — 2026-10-12

### Исправлено
- **Парсер информации о модулях (операция 10)**: тип модуля теперь сопоставляется
  слоту со смещением **+1** (`slot = index + 1`) — по данным реального устройства
  CPU приходит как `index=0` и занимает физический слот 1, DIR12 (`index=4`) —
  слот 5 и т.д. Убрана прежняя автоэвристика «базы индексации», дававшая
  смещение типов на окне «Информация о модулях». Базовая гипотеза +1 фиксируется
  в логе; альтернативные сдвиги (0, +2) проверяются только если дают строго
  меньше конфликтов (защита от прошивок бэкенда без смещения).

### Изменено
- **Запрет прошивки модулей без серийного номера**: модуль, для которого бэкенд
  не вернул `serial_num`, помечается как недоступный для прошивки (`flashable=False`):
  в диалоге информации о модулях строка затемняется, в редакторе СП строка
  заблокирована (тип/версия не заполняются), при записи plan.xml такие строки
  не проходят валидацию, а в лог выводится предупреждение.
- Файл приложения переименован: `MFC_Module_Updater_v1.54.py` → `MFC_Module_Updater_v1.55.py`.

### Добавлено
- CI/CD: имя собираемого `.exe` теперь включает версию приложения —
  `MFC_Flasher_v<APP_VERSION>.exe` (workflow `build-exe.yml` читает `APP_VERSION`
  из исходника); так же именуются артефакт Actions и ассет GitHub Release.
- Пути в `ci.yml` и `pyproject.toml` переведены на шаблон `MFC_Module_Updater_v*.py`,
  чтобы CI не требовал правки при каждом инкременте версии.

## [1.54] — 2026-10-10

### Исправлено
- **Парсер информации о модулях (операция 10)**: устранено смещение типов модулей
  в окне «Информация о модулях» (в первом слоте показывался NA вместо CPU,
  в четвёртом NA вместо DIR12 и т.п.). Причина — неверное предположение о нулевой
  базе индексации массива `module_info_arr`: устройство отдаёт индексы от 1
  (`{"index": 1, "module_type":"CPU", ...}`), а данные раскладывались по позиции
  в массиве. Реализовано автоопределение базы индексации (0 или 1) по содержимому
  ответа; добавлен корректный fallback для `module_type_config` и улучшена
  обработка молчащих модулей из конфигурации креста. В лог выводится строка
  «База индексации …» для контроля на реальном устройстве.

### Изменено
- Файл приложения переименован: `MFC_Module_Updater_v1.53.py` → `MFC_Module_Updater_v1.54.py`.
- Версия приложения вынесена в единственную константу `APP_VERSION`
  (используется в заголовке окна); docstring модуля обновлён.
- CI/CD (.github/workflows): пути в `ci.yml` и `build-exe.yml`, настройки ruff
  в `pyproject.toml` обновлены под новое имя файла.

### Добавлено
- `.github/workflows/build-exe.yml`: автосборка `MFC_Flasher.exe` (PyInstaller,
  onefile, без консоли) на windows-latest — артефакт при ручном запуске и
  автоматический GitHub Release с вложенным .exe при пуше тега `vX.Y.Z`.
- Линтер ruff в CI (`ruff check .`) с точечными исключениями в `pyproject.toml`.
- Этот файл истории изменений (CHANGELOG.md).
