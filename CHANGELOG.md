# История изменений (Changelog)

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версионирование — по принципу `MAJOR.MINOR.PATCH` с инкрементом версии в исходнике
(`APP_VERSION`) при каждой доработке. Начиная с v1.55 собранный `.exe` содержит
версию в имени файла (`MFC_Flasher_v<VER>.exe`).

## [1.79] - 2026-10-20

### Исправлено
- **Update искал файлы из устаревшего плана** (`boot_atb3500_dor12_r.bin` при актуальном plan.xml с `appl_..._R3_4_191026.bin`): «Запустить прошивку» больше не использует локальный файл СП — план всегда выгружается и читается с устройства; валидация перед Update проверяет наличие каждого файла образа на контроллере (рекурсивно по дереву images, по basename); ошибка перечисляет все недостающие файлы.
- **Дублирование строк завершения операций** («--- Операция: ... завершена ---» дважды) — guard `_finished_emitted` ставится до emit во всех путях (run(), тихое сохранение СП, цепочка Автопрошивки); повторные вызовы игнорируются.
- **Строки «Операция ... завершена» не выделялись синим** — порядок веток окраски лога исправлен (синяя ветка раньше красной/обычной).
- **Кнопки «Выбрать все» / «Снять все» в редакторе СП не работали** — обработчики перевязаны на корректные слоты; «Выбрать все» выбирает только flashable-модули с непустым путём и допустимым типом.
- **Автопрошивка**: шаг «Тихий режим» больше не зависает (op 11 → op 13 разделены, состояние цепочки сбрасывается на старте).

### Изменено
- Исходник переименован: `MFC_Module_Flasher_v1.78.py` → `MFC_Module_Flasher_v1.79.py`, `APP_VERSION = "1.79"`.

## [1.78] - 2026-10-20

### Исправлено
- **Дублирование строк `--- Операция: ... завершена ---` и повторный переход цепочки Автопрошивки**: введён единый метод `_emit_finished` — маркер «finished уже эмитирован» ставится строго перед сигналом; двойные emit из `_op13_quiet_save` и `run()` исключены (цепочка больше не «проскакивала» шаги и не зависала).
- **«Файл прошивки boot_..._r.bin не найден» при Запуске прошивки** (хотя на устройстве в plan.xml актуальные имена): проверка наличия файлов теперь опирается на **актуальный plan.xml контроллера** — добавлен рекурсивный поиск по всему дереву `/home/user/fw_update/images` (`_remote_image_names`, файлы шага 1 загружаются с подпапками скана); сопоставление дополнено по basename; сообщение об ошибке перечисляет все отсутствующие файлы сразу.
- **Автопрошивка зависала на шаге 3 («Тихий режим: plan.xml не выгружается…»)**: шаг 3 разбит на два воркера — op 11 готовит данные (модули/план/скан), op 13 собирает строки СП тихим автозаполнением appl (`_auto_build_rows`, без создания диалога в GUI) и сохраняет plan.xml; при старте цепочки сбрасывается состояние предыдущих прогонов (`_auto_failed`, `_auto_rows`), из-за залипания которых цепочка завершалась досрочно.
- **Ложное «Уже выполняется другая операция»** при быстром запуске следующего шага: если предыдущий воркер ещё формально запущен, но уже эмитировал finished, блокировка не применяется.
- **Цвет служебных строк**: ветка окраски логов переставлена — строки «Операция ... завершена с ошибкой» больше не перекрашивались красным до синей ветки; все строки начала/завершения операций и «=== Автопрошивка ===» стабильно синие (#003399 bold).

### Изменено
- **Диалог «Результат прошивки»**: кнопки «Выгрузить дамп» и «ОК» размещены в одном горизонтальном ряду (dump слева, ОК справа).
- Исходник переименован: `MFC_Module_Flasher_v1.77.py` → `MFC_Module_Flasher_v1.78.py`, `APP_VERSION = "1.78"`.

## [1.73] - 2026-10-20

### Добавлено
- **Кнопка «Автопрошивка»** (правая колонка, операция №13): автоматически последовательно запускает цепочку без диалоговых окон:
  1. Внедрение агента и прошивок (тихий режим, с учётом контроля формата);
  2. Создание СП (MakePlan с остановкой/запуском сервисов PrjA*, пауза 15 сек);
  3. Редактор СП в тихом режиме: загрузка plan.xml с устройства, автозаполнение appl, сохранение файла XML на устройство; если ни одна строка не выбрана — предупреждение и остановка цепочки;
  4. Прошивка (Update с контролем результата);
  5. Показ результата прошивки (парсинг operation_log: успех/ошибка/нет информации);
  6. Удаление директории агента и прошивок с контроллера.
- Если на каком-то этапе продолжение невозможно — в операционном логе указывается причина, а очистка директории выполняется по возможности (в `finally`).

### Изменено
- Исходник переименован: `MFC_Module_Flasher_v1.72.py` → `MFC_Module_Flasher_v1.73.py`, `APP_VERSION = "1.73"`.

## [1.71] - 2026-10-19

### Изменено
- **Контроль формата прошивок (расширен)**: теперь проверяются не только файлы `full`, но и имена, в которых парсер не может обнаружить версию, тип модуля или тип прошивки (например, короткие `appl_atb3500_dir12_r.bin`). При включённом контроле (по умолчанию) такие прошивки на устройство НЕ загружаются; при выключенном — загружаются с предупреждением.
- **Операционный лог**: чекбокс «Детализация» перемещён влево от кнопки «Очистить лог». При включённой детализации в логе видны имена всех загружаемых и игнорируемых прошивок; по умолчанию (выключено) скрыты заголовки и тело HTTP-ответа, Payload, «MakePlan stdout», «Статус: 200».
- **Редактор СП**: исправлена работа кнопок «Выбрать все» / «Снять все»; «Выбрать все» выставляет флаги всем модулям, для которых разрешена прошивка (flashable + непустой путь + контроль формата). Если путь к прошивке пуст — флаг выбора снят и чекбокс неактивен.

### Добавлено
- Понятные сообщения «файл ещё не создан» вместо критической ошибки `No such file` при отсутствии plan.xml, дампа, operation_log/result.txt.

### Удалено

## [1.70] - 2026-10-19

- **Два режима операционного лога**: по умолчанию — краткий (без детализации): убраны дублирующие и отладочные сообщения (пер-слотовые строки парсера «Слот N: тип не определён/резерв», сводка «Соответствие слот/тип», «Проверка: тип ...», списки файлов с проблемами формата); вместо них — ёмкие сводки («ВНИМАНИЕ: файлов с проблемами формата — N...», «Итог result.txt: успешно N, с ошибками M (слоты: ...)»). Опция «Подробный операционный лог (с детализацией)» в форме возвращает полную детализацию.
- **Редактор СП**: если путь к файлу прошивки пуст — чекбокс выбора модуля снят И неактивен (с подсказкой); выбор восстанавливается автоматически при заполнении пути (при наличии найденной прошивки и прохождении контроля формата).

### Добавлено
- Настройка `verbose_log` в JSON-конфиге (по умолчанию `false`).

### Исправлено
- **Создание СП без контроля формата**: теперь действительно допускает сохранение сценария с некорректными именами и форматом `full` — раньше файл без полного имени всё равно отсекался валидацией. Такие строки собираются в одно окно предупреждений («Сохранить сценарий?»), сохранение возможно. При включённом контроле формат `full`/некорректные имена по-прежнему запрещены, а на устройство они не загружаются (и потому не могут попасть в СП через автозаполнение).
