# MFC Module Updater (MFC_Flasher) v1.53

Настольное GUI-приложение (PyQt6) для прошивки модулей многофункционального
контроллера (МФК / IskraIO). Автоматизирует полный цикл обновления прошивок:
загрузку агента и файлов на устройство, формирование и редактирование сценария
прошивки (СП), запуск прошивки, анализ результатов и выгрузку логов.

Связь с устройством:
- **SSH/SFTP** (paramiko) — работа с агентом `IskraIO_Util` в каталоге
  `/home/user/fw_update/` на устройстве;
- **HTTP API** (`/vx3/backend.fcgi`) — получение информации о модулях
  (запрос `IskraIOGetAll`) с двухшаговой авторизацией (token + SID).

## Основные возможности

| Операция | Описание |
|---|---|
| Загрузить агента | Создание `/home/user/fw_update/images`, загрузка `IskraIO_Util` и файлов прошивок по SFTP |
| Создать СП | Остановка сервисов телемеханики, запуск `IskraIO_Util MakePlan`, запуск сервисов |
| Импортировать СП | Загрузка локального `plan.xml` на устройство (с бэкапом текущего) |
| Экспортировать СП | Выгрузка `plan.xml` с устройства |
| Запустить прошивку | `IskraIO_Util Update` с индикатором прогресса, выгрузка `operation.log`, анализ `result.txt` |
| Просмотр результата | Таблица «слот → результат» из `plan.xml` + `result.txt` |
| Выгрузить дамп | Выгрузка `io.can.box2.csv` с устройства |
| Редактировать СП | Диалог редактирования сценария: выбор модулей, путей и типов прошивок, автозаполнение по типу модуля, валидация имен файлов и версий |
| Информация о модулях | Таблица модулей через HTTP-бэкенд (тип, серийный номер, версии FW/HW) |

## Требования

- Python 3.9+
- PyQt6, paramiko (см. `requirements.txt`)
- Сетевой доступ к МФК по SSH (root) и HTTP

## Установка и запуск

```bash
git clone <URL репозитория>
cd MFC_Flasher
python -m venv venv
# Windows:
venv\Scripts\activate
# Linux/macOS:
source venv/bin/activate

pip install -r requirements.txt
python MFC_Module_Updater_v1.53.py
```

Для сборки исполняемого файла (по желанию):

```bash
pip install pyinstaller
pyinstaller --onefile --windowed --name MFC_Module_Updater MFC_Module_Updater_v1.53.py
```

## Конфигурация

Параметры подключения и пути задаются в окне приложения и сохраняются в
`mfc_flasher_config.json` рядом с запускаемым файлом:

| Ключ | Описание |
|---|---|
| `ip` | IP-адрес МФК |
| `password` | Пароль пользователя root (SSH) |
| `agent_dir` | Локальная директория с агентом `IskraIO_Util` (сюда же выгружаются логи/дампы) |
| `firmware_dir` | Директория с файлами прошивок |
| `plan_xml` | Локальный файл сценария прошивки |
| `api_path` | Путь HTTP-API (по умолчанию `/vx3/backend.fcgi`) |

> ⚠️ **Внимание:** `mfc_flasher_config.json` содержит пароль root и **не должен
> попадать в репозиторий** — он добавлен в `.gitignore`.

## Формат имени файла прошивки

Ожидается имя из 7 частей, начинающееся с `full_`:

```
full_<МАРКЕР>_<ТИП>_<...>_R<мажор>.<минор>_<ДДММГГ>.bin
пример: full_ATB1_GSM_XX_R2.7_010225.bin
```

- `АРТЕФАКТ PSU` нормализуется в тип `POWER_UNIT`;
- маркеры вида `ATBxxx` приводятся к `ATB xxx`;
- файлы, не соответствующие формату, игнорируются с предупреждением в логе.

### Архитектура кода (один файл)

- `SSHClient` — обертка над paramiko (exec, sftp get/put/chmod/stat/listdir);
- `BackendClient` — HTTP-клиент бэкенда: `get_token` → запросы с token/SID,
  повтор при протухшей сессии (`result == 2`, не более 3 попыток), отладочный
  лог в `http_debug.log`;
- `parse_plan_xml`, `parse_result_txt`, `parse_firmware_filename`,
  `normalize_fw_version` — разбор данных и имен файлов;
- `OperationWorker (QThread)` — выполнение операций 1–11 вне GUI-потока,
  сигналы `log_signal` / `progress_signal` / `finished_signal`;
- `ModuleInfoDialog`, `ViewResultDialog`, `EditSPDialog` — диалоги;
- `MainWindow` — форма, конфигурация, журнал операций (цветная подсветка).

## Рабочий процесс (типовой цикл прошивки)

1. Указать IP, пароль, директорию агента и директорию прошивок.
2. **Загрузить агента** (операция 1).
3. **Создать СП** (операция 2) — остановит телемеханику, выполнит `MakePlan`.
4. При необходимости — **Редактировать СП** (операция 9): автозаполнение,
   выбор прошивок, сохранение `plan.xml` на устройство.
5. **Запустить прошивку** (операция 6).
6. **Просмотр результата** (операция 8), при необходимости — выгрузка дампа (7).

## Примечания и известные ограничения

- Все операции выполняются от пользователя **root** по SSH; используйте только
  в доверенной сети. Используется `AutoAddPolicy` (ключи хостов не проверяются).
- HTTP-API работает по незащищенному `http://` — это особенность устройства.
- Отладочный лог `http_debug.log` пишется в текущую директорию при каждом
  создании `BackendClient` (перезаписывается).
- Операции «Создать СП» и «Прошивка» останавливают сервисы `PrjA.service` и
  `PrjA-tele.service` и гарантированно перезапускают их в `finally`.
