# Руководство пользователя — MFC Module Flasher

Краткое руководство по утилите прошивки модулей многофункционального контроллера (МФК / IskraIO).
Актуально для версии **v1.97**.

---

## 1. Установка и запуск

### Готовый exe (Windows)
1. Скачайте `MFC_Flasher_v<версия>.exe` со [страницы релизов](https://github.com/XHunter1980/MFC_Flasher/releases/latest).
2. Запустите двойным щелчком (установка не требуется). При первом запуске Windows SmartScreen может предупредить о неподписанной программе — «Выполнить в любом случае».

### Из исходников
```bash
pip install -r requirements.txt
python MFC_Module_Flasher_v1.97.py
```
Требуется Python 3.10+ с PyQt6 и paramiko.

## 2. Главное окно

### Группа «Подключение и пути»
| Поле | Назначение |
|---|---|
| **IP-адрес МФК** | адрес контроллера в сети (например, `172.16.2.3`) |
| **Пароль root** | пароль SSH-пользователя root на контроллере |
| **Файл агента** | полный путь к исполняемому файлу `IskraIO_Util` (не к папке!) |
| **Директория прошивок** | папка с файлами прошивок на ПК (сканируется рекурсивно, включая подпапки `appl/`, `boot/`, `full/`) |

Флаги:
- **Контроль формата прошивок** (по умолчанию включён) — файлы с некорректными именами и формат `full` не загружаются на устройство и не используются для прошивки. При выключении — только предупреждения, загрузка разрешена.
- **Не прошивать при совпадении версий** (по умолчанию включён) — у модулей, где уже стоит та же версия прошивки, флаги выбора снимаются автоматически.

Все настройки автоматически сохраняются в `mfc_flasher_config.json` рядом с программой.

⚠️ Файл конфигурации содержит пароль root в открытом виде — не переносите его на чужие машины и не выкладывайте в публичные репозитории.

### Кнопки операций (параллельно выполняется только одна операция)

| Левая колонка | Правая колонка |
|---|---|
| **АВТОПРОШИВКА** (большая кнопка) | Создать СП |
| Внедрить агента и прошивки | Импортировать СП |
| Запустить прошивку | Экспортировать СП |
| Просмотр результата | Редактировать СП |
| Удалить агента | Информация о модулях |

### Журнал (операционный лог)
Внизу — цветной журнал хода операций: начало/завершение операций выделяются синим, ошибки — красным. Флаг **«Детализация»** (слева от «Очистить лог», по умолчанию выключен) включает вывод HTTP-payload, заголовков и тел ответов, MakePlan stdout и имён всех загружаемых/игнорируемых прошивок — полезен при отладке.

## 3. Подготовка файлов прошивок

Имя файла должно начинаться с префикса типа образа:

| Префикс | Значение | Поддержка |
|---|---|---|
| `appl_` | приложение (рабочая прошивка) | ✅ |
| `boot_` | загрузчик | ✅ |
| `full_` | полный образ | ⚠️ пока не поддерживается (предупреждение; без контроля формата загрузится, но прошивка заблокирована) |

Полное имя вида: `appl_<маркер>_<тип>_R<версия>_<дата>.bin`, например
`appl_atb3500_dir12_R3_4_191026.bin` — версия `R3.4` (допустимо и `R3.4`, а не R3_4), дата 19.10.2026.
Допускаются и короткие имена (`appl_atb3500_dir12_r.bin`) — но при включённом контроле формата они считаются некорректными и не загружаются.
Дата в имени обязательна в формате ДДММГГ, формат ДДММГГГГ (например 19102026 будет считаться некорректным)

ВНИМАНИЕ!!! Автозаполнение, в частности в автопрошивке, выполняется только с корректными именами прошивок

## 4. Типовой рабочий процесс (вручную)

1. **Информация о модулях** — проверить состав креста (слоты, типы, серийные номера, текущие версии). Модули без серийного номера прошить нельзя — они помечены «модуль отсутствует» / «слот пуст» / «резерв».
2. **Внедрить агента и прошивки** — загрузка `IskraIO_Util` и файлов прошивок на контроллер (каталог `/home/user/fw_update/`).
3. **Создать СП** — генерация сценария прошивки на устройстве (MakePlan; сервисы PrjA* будут остановлены и перезапущены, ожидание ~20 сек).
4. **Редактировать СП** — открытие редактора сценария (см. раздел 5).
5. **Запустить прошивку** — выполнение Update по сохранённому plan.xml.
6. **Просмотр результата** — окно результатов: слот, тип, путь, тип образа, версии до → после, результат («Выполнено» / ошибка). Здесь же кнопка **«Выгрузить дамп»** (csv-дамп CAN-бокса). Локальная копия файла результата сохраняется на ПК автоматически до очистки устройства.
7. **Удалить агента** — удаление рабочего каталога агента и прошивок с контроллера (выполняется вручную, когда прошивка проверена).

Полезно: **Экспортировать СП** сохраняет plan.xml с устройства на ПК, **Импортировать СП** загружает подготовленный файл сценария на контроллер.

## 5. Редактор СП

Открывается по кнопке «Редактировать СП» (или автоматически внутри Автопрошивки в тихом режиме). При открытии **автоматически выполняется автозаполнение appl**.

Колонки таблицы: **Выбор** (флаг прошивки), Слот, Тип модуля, Инфо, Путь к файлу, в.МФК (версия на устройстве), в.СП (версия из плана), Дата, Тип прошивки (`appl` / `boot`).

Кнопки:
- **Автозаполнение appl / Автозаполнение boot** — подбирают файлы прошивок из указанной директории по типу модуля и выбранному типу образа (формат `full` не выбирается); всплывающих окон нет, итог — в журнале.
- **Выбрать все** — отмечает модули, для которых разрешена прошивка (есть серийный номер, непустой путь, версия отличается при включённом флаге совпадения).
- **Снять все** — снимает все флаги (с первого нажатия).
- **Сохранить / Отмена** — запись plan.xml на устройство (корень `<Root>`, атрибут `type="appl"|"boot"`) или закрытие без сохранения.

Правила:
- Пустой путь к файлу ⇒ флаг выбора снят и недоступен.
- Резервы широких модулей (второй слот CPU, POWER_UNIT и т.п.) имеют пустой неактивный путь и не прошиваются.
- Для модуля из директории `full` можно выбрать `appl` или `boot`; из `appl` — только `appl`; из `boot` — только `boot`.
- Сохранить план можно и с нуля выбранных строк (будет предупреждение).

## 6. Автопрошивка

Большая зелёная кнопка **АВТОПРОШИВКА** запускает цепочку без диалоговых окон:

1. Внедрить агента и прошивки
2. Создать СП (ожидание ~20 сек)
3. Редактор СП в тихом режиме: автозаполнение appl + сохранение plan.xml
4. Запустить прошивку

После завершения в журнале печатается итог по каждому модулю («Слот N (тип): успешно/ОШИБКА, с версии X на Y»), затем открывается окно результатов. Рабочий каталог агента с устройства **не удаляется** — очистите его кнопкой «Удалить агента» после проверки. Если любой шаг невозможен — в журнале указывается причина, цепочка прерывается.

## 7. Устранение неполадок

| Симптом | Решение |
|---|---|
| «Подключение не установлено» (WinError 10061) при HTTP-запросах | Проверьте IP и что бэкенд контроллера запущен (сервисы PrjA* активны; во время прошивки они остановлены — это нормально) |
| «Файл прошивки ... не найден» | Проверьте, что файл есть в директории прошивок на ПК и загружен на устройство; включите «Детализацию» — в логе видно, какие файлы игнорируются контролем формата |
| Прошивка не стартует, кнопки неактивны | Идёт другая операция — дождитесь её завершения (строка «--- Операция ... завершена ---») |
| Модуль не выбирается для прошивки | Нет серийного номера (модуль отсутствует/резерв/пустой слот) либо пуст путь к файлу |
| Не видно подробностей ошибок | Включите флаг «Детализация» и повторите операцию; лог HTTP сохраняется также в `http_debug.log` |

---

## 8. Безопасность

- Все операции выполняются по SSH от имени root — соблюдайте осторожность в производственных сетях.
- Пароль хранится в `mfc_flasher_config.json` в открытом виде.
- Управление ведётся по незащищённому HTTP (`/vx3/backend.fcgi`) — используйте только в изолированной сети контроллера.
